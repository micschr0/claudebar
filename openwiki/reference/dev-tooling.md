# Dev tooling

Conventions and tools for contributors.

## Agent instruction files

- Top-level `AGENTS.md`/`CLAUDE.md` reference the wiki
  (`## OpenWiki` section).
- `.claude/CLAUDE.md` (private, gitignored) carries the detailed project
  conventions: tech stack, backward-compat constraints, CI targets, module
  structure, error handling, feature gating, dependency-injection pattern.

## Static analysis

- `cargo clippy -- -D warnings` — lint gate (no `.clippy.toml`).
- `cargo fmt` — standard formatting.
- `shellcheck` — bash lint (lint task).
- `actionlint` — GitHub Actions workflow validation.

## Taskfile (`Taskfile.yml`)

Task aliases: build, test, lint, render, screenshots, benchmark,
`build-minimal` (`--no-default-features`).

## Changelog

- `cliff.toml` — git-cliff rules; generated into `CHANGELOG.md` on release.

## Coverage discipline

- Baseline ~74% (`llvm-cov`, `covrs`).
- TUI `mod/ui/preview` intentionally 0% (UI shell, verified by screenshot
  scripts) — stated in `CONTRIBUTING.md`.
- `app.rs`/`sample.rs` have real unit tests.

## Docs deploy

- `docs/` static site (styles.css, index.html generated by `gen-gallery.sh`),
  deployed via `pages.yml`. `docs/` is excluded from the OpenWiki corpus
  (`.openwikiignore`).

## Wiki self-maintenance

- `.github/workflows/openwiki-update.yml` runs `openwiki code --update`
  nightly; opens a PR when docs change.
- `.openwikiignore` keeps the doc agent on the Rust core (excludes docs/
  video/ screenshots/ assets/ tmp/ scripts/).
